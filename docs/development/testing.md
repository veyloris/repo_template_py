# Testing doctrine

Tests come before implementation. The type checker proves types; tests prove
behavior. Every bug fix starts with a failing test that reproduces it.

## The layer model

Structure the package so each layer gets the cheapest test that actually
proves it:

| Layer | Contents | Test style |
|---|---|---|
| Domain core | Pure functions over plain data, no I/O imports | Unit + property tests, exhaustive |
| Adapters | Files, subprocesses, devices, network clients | Integration tests, golden files |
| CLI | argparse wiring over the core and adapters | `main(argv)` with `capsys` and hand-written fakes |
| End-to-end | The installed console script | A few runs of the real entry point |

The domain core (calculations, rules, state machines) takes and returns plain
data: dataclasses, numbers, strings, arrays. I/O lives in adapters. Code that
needs an adapter takes a narrow `typing.Protocol` rather than importing the
concrete class, so a test passes a fake that satisfies the protocol.

Purity is not enough on its own: pure code must also be *reachable* without
I/O. A calculation that can only be called through an object whose
constructor opens a file or a device is untestable in practice, however pure
its body. Split load from compute and export the compute.

## Organization

- Tests live in `tests/`, mirroring the package: `src/my_app/score.py` ->
  `tests/test_score.py`.
- Plain pytest functions with plain `assert`. `pytest.mark.parametrize` for
  tables. Fixtures for shared setup; `tmp_path` for anything on disk.
- Doubles are hand-written fakes implementing the narrow protocols. Patching
  module attributes with `unittest.mock` is the exception, used only at a
  boundary the code does not own, and named for intent in the test.
- `filterwarnings = ["error"]` is set: a warning is a failure until a test
  says why it is expected.
- Tests that need hardware, a network, or a slow external tool are marked
  (register the marker in `pyproject.toml`) and skipped by default, so
  `uv run pytest` is always a self-contained gate.

## A test that cannot fail proves nothing

When a test goes green on first run, make it go red once: break the code it
covers (or feed it the input it guards against) and watch it fail. A probe
that would have passed either way is not evidence. The same holds for golden
files and for fixtures whose values are degenerate: a fixture where every
branch takes its empty-input path produces green tests that bind nothing.

## Golden-file tests: parsers and reports

File-format parsers and report renderers are tested against `tests/data/`
fixtures with committed golden outputs. Regenerate with an explicit opt-in
(`UPDATE_GOLDEN=1 uv run pytest`), never automatically, and review the diff
like code.

Fixture rules:

- Fixtures derived from real inputs are scrubbed of personal data before
  commit, say so in the filename (`...-SCRUBBED...`), and carry a note
  distinguishing fake identity from real data shapes.
- Prefer synthetic fixtures generated by a seeded, deterministic function
  over captured real data. A git-tracked fixture carries none of the access
  controls its source had.

## Differential tests: porting an existing system

When reimplementing something that already runs, the acceptance gate is a
differential harness, not spot checks: feed the same input to both
implementations and compare every output field. Compare exact types exactly
and floats within a stated tolerance. Keep the reference implementation, or a
recording of its outputs, in `tests/data/` so the harness is self-contained.

## Property tests

Pure parsers, codecs, and calculations get hypothesis property tests next to
the example tables. Round-trip fixed points (`parse(render(x)) == x`) and
invariants (monotonicity, conservation, bounds) are the workhorses.

## Performance

- A performance claim needs a measurement, not a subtraction. Before/after
  means the same command, the same input size, the same machine.
- A benchmark states a written acceptance target and its rationale. A
  benchmark with no target cannot fail, so it cannot regress.
- No wall-clock assertions in tests. Shared CI runners are too noisy for a
  latency threshold; it fails on neighbors, gets marked flaky, and then gets
  deleted. Only correctness invariants may fail a benchmark.
- The template ships no benchmark tooling. The first real hot path adds it
  (pytest-benchmark or a plain timing script) as a D-### entry.
